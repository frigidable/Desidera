# Desidera — аудит GUI, UX и доступности, 14 ноября 2026

**Основание:** состояние main, коммит 14ad913b46269243e0fa1141d180d6f9f53daaa6, исходный код PySide6, тесты, существующие правила AGENTS.md и документы docs/ux. После первого коммита PR #93 дополнительно просмотрены отдельные офлайн Windows/Qt screenshot captures (см. раздел 8); живой интерактивный Windows-сеанс не проверен. Оценка визуального качества и соответствие WCAG не сертифицированы.

**Цель:** астроном, работающий с одной галактикой, должен без догадок создавать/возобновлять проект, находить локальные FITS, понимать источник и ограничения измерений, выполнять воспроизводимые операции и исправлять ошибки, не затрагивая оригинальные наблюдения.

**Границы:** только GUI, UX, доступность и тестовые интерфейсные контракты. Нельзя менять научные результаты, WCS, конвенции RA/Dec/PA, карты MASKBITS/INVVAR/NEXP, проверку идентичности объекта, привязку FITS, загрузку данных или статус SCIENCE HOLD. Вся photometry / PSF / sky / SBF физика вне настоящего изменения.

## 1. Краткая оценка интерфейса по исходному коду

Реализованная архитектура значительно шире первоначальной демонстрации: Project Hub, GalaxyDetailCard, Survey Explorer, Data Manager, FITS Explorer, Photometry Workspace, PSF-0, Scene & Masks, QA и исторические отчёты. GUI не является только макетом. В текущем коде уже есть объектный UUID, восстановление сохранённых операций, кэшированные предпросмотры, подробные ограничения исходных данных, контролируемые асинхронные задачи и множество offline Qt tests. Эти функции не следует перепроектировать с нуля.

Наиболее опасная проблема для нового пользователя — раздробленное объяснение последовательности работы: видимые команды Survey, Files, FITS, Data Manager, Photometry и QA не всегда образуют одну непротиворечивую цепочку действий. Дополнительные научные операции должны открываться по соответствующим предпосылкам, а пользователь в любой момент должен видеть галактику, полосу, релиз, источник и статус доказательности.

Ниже различаются:
- **Доказанный дефект кода** — конкретное условие присутствует в текущем исходнике.
- **Подтверждённое UX-ограничение** — поведение непосредственно следует из реализации, но оценка его тяжести требует сценарной проверки.
- **Риск, требующий проверки** — нельзя утверждать, что визуальный дефект возник, пока нет проверенного скриншота или реального взаимодействия.

Обозначения приоритета: P0 — блокирует основную работу/понимание данных, P1 — существенно влияет на удобство/доступность, P2 — улучшение после стабилизации.

## 3. Целевой рабочий сценарий

### A. Создать или открыть галактику

На старте показывать Galaxy Projects, с единственной главной командой «New galaxy project», поиском и историей. Пустой проект без координат допустим. При вводе только RA либо только Dec кнопка создания должна оставаться недоступной с видимой причиной. Имя, ICRS, локальная папка и запрет на перезапись оригинальных файлов должны быть понятны до подтверждения. При повторном открытии сверяется UUID и неизменяемый паспорт. Если папка перемещена, пользователь выбирает relink исходной идентичности, а не произвольный другой объект.

### B. Проверить данные

После открытия показывать выбранные релиз/область/brick/band и состояние оригинального science quartet. Если data root отсутствует — предложить привязать существующий каталог. Если часть FITS есть — указать точные недостающие продукты. Если 4/4 имеются — не заявлять валидность без проверки заголовков, размеров/WCS, калибровок и relevant QA. Повторная загрузка уже имеющихся файлов не должна запускаться при открытии проекта.

### C. Исследовать изображение

FITS Explorer должен использовать native FITS как источник, отдельно объяснять display stretch и native raw pixel values. При смене IMAGE/INVVAR/NEXP/MASKBITS — единицы, смысл цветовых оверлеев и недоступные пиксели. Пользователь может отладить диапазон отображения, но это не изменяет измерения. Полоса, ICRS, источник, статистический статус и исходные файлы остаются доступными. Различие display-only RGB и science FITS показывается непосредственно около изображения, а не только в tooltip.

### D. Запустить анализ и вернуться к нему

Показывать prerequisites и причину blocked, running, cancel requested, completed diagnostic, failed, stale. После перезапуска восстанавливать только подтверждённые сохранённые состояния, а не выдавать старый результат за свежий. После request stop сообщение не должно обещать немедленную остановку: checkpoint может наступить позже, а ранее записанные immutable receipts сохраняются. QA должно оставаться доступным для повторной проверки.

## 4. Доступность: проверяемые требования

1. Полный keyboard-only маршрут: открыть Hub → Ctrl+F → выбрать объект стрелками → Enter → вернуться; Ctrl+N → заполнить форму через Tab / Shift+Tab → создать или отменить без мыши.
2. Каждый текстовый ввод имеет имя с единицами, не полагается только на placeholder. Error-state формы сообщается текстом; disabled submit не устраняет необходимость показывать объяснение.
3. При focus переходе на scrollable/folded panels активный элемент остаётся видимым. У элементов не должно быть нулевых hit targets или невидимого focus ring.
4. Системный масштаб 100/125/150/200%; базовые видимые подписи желательно >=12 px, без horizontal text clipping. Цвета и контрасты проверяются по итоговому рендеру.
5. Статус «failed/warning/QA not adopted» должен быть читаем без различения цвета. Иконки и маски имеют текстовое объяснение.
6. Встроенный FITS canvas требует независимого пользовательского маршрута для чтения значений/координат без обязательного наведения мыши; реализация и проверка остаются следующей задачей.
7. Qt accessibleName и accessibleDescription — только базовый уровень. Фактические NVDA announcement/focus order требуют ручной проверки на Windows.
8. Сообщения об ошибках должны быть короткими в основном поле и доступны полностью в details/copy, не прятаться из-за высоты QLabel.

## 5. Сценарии и критерии приёмки

| Сценарий | Подтверждение |
| --- | --- |
| Первый запуск без проектов | Главная команда видима, не начинается загрузка science FITS, пустое состояние объясняет создание и импорт |
| Новый объект без координат | Создание разрешено и не даёт выдуманного ICRS |
| Только RA / только Dec / Dec за диапазоном | Create disabled, причина видима; на диске не появляются файлы |
| Корректная пара sexagesimal | Создание разрешено, исходные строки интерпретируются по существующему parser contract |
| Search + selection keyboard | Ctrl+F, arrows и Enter позволяют найти/открыть без мыши |
| Существующий проект, no data root | Предложен relink, no auto-redownload |
| Папка проекта заменена другой галактикой | UUID mismatch блокирует open/auto-resume |
| Существующие FITS 4/4, QA not run | Метка «есть, не проверены», а не подтверждённая научная готовность |
| Wrong/missing WCS, incomplete NEXP | Состояние явно объясняет причину и действия; не разрешает science adoption |
| Длинное сообщение ошибки / offline remote | Нет обрезания критической информации, работа с локальными данными доступна |
| Пользователь остановил background task | Нет ложного COMPLETED, immutable receipts не удаляются |
| FITS на 1366×768 и 150% DPI | Canvas остаётся полезным, цветовая легенда и display inputs доступны |
| NVDA + color-blind/high contrast | Озвучивание контекста, нормальное отображение focus/ошибок и несводимость масок только к цветам |

Тесты в этой ветке дополняют только программно проверяемую часть: Create dialog, window shortcuts, list activation, FITS display accessibility и явный статус DIAGNOSTIC_NOT_ADOPTED. Для сценариев с реальными FITS, высокими DPI и NVDA нужны отдельные измерения; утверждать их прохождение по коду нельзя.

## 6. Последовательность доработок

**Пакет 1 — реализован в предлагаемом изменении:** быстрые клавиатурные действия Galaxy Project Hub, семантика screen-reader names, защита формы от некорректных координат, доступные метки FITS controls и читаемость критического научного статуса.

**Пакет 2 — после screenshot QA:** устранение обрезания сообщений, проверка 125–200% DPI, экранных контрастов и фокусных переходов в Project Hub/FITS/Survey Explorer. Уточнение сообщений о восстановлении и доступная история операций.

**Пакет 3 — после реального пользовательского теста:** интерактивный keyboard pixel inspector, управление auto-RGB privacy, единая система состояния prerequisite/blocked/stale и профессиональный onboarding для впервые работающего с DESI пользователя.

**Пакет 4 — по результатам научной валидации:** только после отдельных методических приёмок — расширенная научная диагностика PSF/sky, полная фотометрия и SBF. GUI не должен обещать научную готовность невалидированной функции.

## 7. Что нельзя считать завершённым

- Этот документ — E0 source review; тесты/скриншоты/UX-проверка имеют собственные evidence уровни.
- Успешная сборка/запуск не подтверждает качества screen-reader взаимодействия, контраста или 4K/high-DPI.
- Наличие Python-класса или вкладки не доказывает, что конечный астрономический результат валидирован.
- Ни одна из предложенных UX доработок не разрешает автоматического изменения/перезаписи science FITS, принятия SIMBAD/NED кандидатов или сброса SCIENCE HOLD.

Рекомендуемый итоговый gate: все офлайн GUI tests и научные регрессии на точном PR-head, сравнение снимков каждого экранного состояния при 1366/1600/1920, затем ручной Windows+NVDA/FITS сценарий. Merge только после review владельца проекта.

## 18. Scene Editor: задачи вместо одной длинной панели

По исходному виджету Scene SC1 правую колонку составляли подряд параметры ручного рисования, SGA, множество экспериментальных изофотных/масочных инструментов, список черновых правок и операции сохранения. Пользователь вынужден был прокручивать десятки нерелевантных элементов при каждой смене действия.

**UI-only изменение:** три всегда видимые компактные кнопки задач `Draw / Isophote / SGA` управляют одним QStackedWidget. В каждый момент открывается одна осмысленная рабочая область; нет дополнительного меню/accordion на переключении между задачами. Численные поля, черновые области и история сохраняются при смене задачи. `Save scene draft`, `Copy QA` и текущий статус всегда закреплены под прокручиваемой частью правой колонки. Верхние заголовки и научное предупреждение сокращены; полная оговорка доступна в tooltip. Системные Qt palette и доступные названия задач сохраняются.

**Безопасность:** при уходе из Draw незавершённые вершины (ещё не создавшие SkyMaskEdit) явно сбрасываются с текстовым статусом, опубликованные edit-объекты/ревизии не изменяются. ### E2-проверка Scene: выявлен и исправлен горизонтальный overflow

В Windows offscreen-снимках commit `d967201` (запуск 43541312799, оба workflows успешны) три задачи визуально отделены и pinned Save/Copy QA видны, однако **на всех трёх страницах** у правой колонки присутствовала горизонтальная прокрутка. На Isophote это обрезало Smooth px, на Draw — Cancel shape, на SGA — длинные подписи выборов. Это реальный дефект reflow, а не обычный тестовый шум.

Исправлено: порог и сглаживание изофоты переведены из 4-компонентной строки в двухстрочную форму, Undo/Redo/Redraw/Remove — в сетку 2×2, кнопки и чекбоксы получили короткие подписи с полными accessible names/tooltip для неоднозначных действий. Верхние параметры FITS сведены в одну строку, чтобы не дублировать панель растяжения. Экспериментальные сведения `Radius sweep`/`Mask policy` больше не показывают длинные сообщения `not run/invalidated`, если эксперимент не запускался; при запуске или ошибке реальный статус показывается. В скриншотном сценарии и GUI-тестах добавлен fail-closed критерий `horizontalScrollBar().maximum() == 0` при 1366×768/1000×700, а не простое сокрытие полосы.

Научная семантика переключателей и алгоритмов не меняется; их описания сохраняются в tooltips и QA. Требуется exact-head CI и повторный E2.
